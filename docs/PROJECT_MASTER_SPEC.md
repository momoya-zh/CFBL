# 第一部分：项目概述

## 1.1 项目名称

基于深度学习的图像超分辨率重建系统的设计与实现。

## 1.2 项目背景

图像超分辨率重建（Image Super-Resolution，简称 SR）是数字图像处理领域的重要研究方向，其主要目标是从低分辨率图像中恢复出具有更高空间分辨率的图像。

传统图像放大算法主要通过插值计算估计新增像素，具有计算简单、运行速度快、无需训练等优点，但难以恢复图像中已经丢失的纹理、边缘和细节。

深度学习方法可以通过大量图像样本学习低分辨率与高分辨率图像之间的映射关系，从而在图像重建过程中恢复部分纹理和结构信息。

本项目通过实现传统插值算法和深度学习超分辨率模型，构建一个完整的图像超分辨率重建系统，并通过统一实验条件比较不同方法的重建效果。

## 1.3 项目目标

完成一个具备以下能力的图像超分辨率系统：

1. 支持用户上传图片。
2. 支持最近邻、双线性和双三次插值。
3. 支持 SRCNN 和 ESPCN 两种深度学习模型。
4. 支持 2× 和 4× 放大。
5. 四套深度学习模型均从随机初始化开始自主训练。
6. 能够展示不同算法的重建结果。
7. 能够测量图像处理时间。
8. 能够对具有 HR 参考图像的测试样本计算 PSNR 和 SSIM。
9. 能够导出实验数据、结果图片和对比图表。
10. 提供基于 Gradio 的可交互系统界面。

## 1.4 项目范围

本项目采用平衡型实施方案，优先保证系统完整、实验可复现和结果可信。

**必须完成：**

- 三种传统插值算法。
- SRCNN 模型。
- ESPCN 模型。
- 2×、4× 两种放大倍率。
- 四套模型自主训练。
- 统一实验数据与评价协议。
- PSNR、SSIM 评价。
- 推理耗时测量。
- Gradio 交互界面。
- 项目文档、实验报告和答辩材料。

**明确不做：**

- GAN 超分辨率模型。
- Transformer 超分辨率模型。
- 扩散模型。
- EDSR、SwinIR 等额外大型模型。
- 视频超分辨率。
- 盲超分辨率。
- 多 GPU 分布式训练。
- 复杂账户系统。
- 在线模型托管或云端训练服务。

# 第五部分：核心算法设计

## 5.1 传统插值算法

系统实现三种传统图像放大算法。

| 算法 | OpenCV 常量 |
|---|---|
| 最近邻 | `cv2.INTER_NEAREST` |
| 双线性 | `cv2.INTER_LINEAR` |
| 双三次 | `cv2.INTER_CUBIC` |

支持 2×、4×。

统一接口：

```python
upscale_image(image, scale, method)
```

已经在阶段 3 实现，后续优先复用，不得无理由重写。

> **2026-11-13 偏离说明（编号 C-1，详见第十六部分）：** 本节的"优先复用"针对 OpenCV 实现。
> 阶段 4 已冻结"全链路 Pillow BICUBIC（`a = -0.5`）"作为退化与 SRCNN 预上采样的唯一口径；
> `cv2.INTER_CUBIC` 属 `a = -0.75` 的另一族核。因此**阶段 6 的双三次基线必须按 Pillow 重算**，
> 不得直接引用阶段 3 的 OpenCV 数值（实测两族核在真实图像上造成 0.16–0.41 dB 基线漂移）。
> 阶段 3 的 `upscale_image`（OpenCV）保留原样，仅作为传统算法演示用途。

传统插值主要用于基线对比，不承担模型训练功能。

## 5.2 SRCNN

SRCNN（Super-Resolution Convolutional Neural Network）是经典卷积神经网络超分辨率模型。

其主要思路：

1. 先通过双三次插值将 LR 图像放大到目标尺寸。
2. 使用卷积神经网络进一步恢复细节。
3. 输出与 HR 图像尺寸相同的重建结果。

输入：

- 已经 Bicubic 放大的 RGB 图像。

输出：

- 与目标 HR 图像尺寸一致的 RGB 图像。

设计要求：

- 使用 PyTorch 实现。
- 从随机初始化开始训练。
- 不加载外部预训练权重。
- 支持 2×、4× 两套配置。
- 具体网络层数、卷积核大小和激活函数在阶段 4 详细设计中冻结。
- 训练输入预处理与推理输入预处理必须一致。

## 5.3 ESPCN

ESPCN（Efficient Sub-Pixel Convolutional Neural Network）通过子像素卷积实现空间分辨率放大。

其主要思路：

1. 输入低分辨率图像。
2. 在低分辨率空间提取特征。
3. 使用卷积层生成子像素特征。
4. 通过 Pixel Shuffle 重排通道，得到高分辨率图像。

输入：

- 原始 LR 图像。

输出：

- 与目标 HR 图像尺寸一致的重建图像。

设计要求：

- 使用 PyTorch 实现。
- 从随机初始化开始训练。
- 不加载外部预训练权重。
- 支持 2×、4× 两套配置。
- 正确使用 Pixel Shuffle。
- 不得将 SRCNN 的输入处理流程直接套用到 ESPCN。
- 具体网络层数和通道配置在阶段 4 详细设计中冻结。

## 5.4 四套模型配置

必须训练以下四套模型：

| 模型 | 放大倍率 | 是否独立训练 |
|---|---:|---|
| SRCNN | 2× | 是 |
| SRCNN | 4× | 是 |
| ESPCN | 2× | 是 |
| ESPCN | 4× | 是 |

不得将一个倍率的权重直接当作另一个倍率的正式训练结果。

不得使用预训练权重冒充自主训练。

# 第六部分：训练方案

## 6.1 数据预处理

采用统一 RGB 数据流程。

基本流程：

```text
读取 HR 图像
      │
      ▼
RGB 格式统一
      │
      ▼
根据放大倍率生成 LR
      │
      ▼
HR 与 LR 空间配对
      │
      ▼
随机裁剪训练 Patch
      │
      ▼
随机翻转与 90° 旋转
      │
      ▼
转换为 Tensor
      │
      ▼
送入模型训练
```

要求：

- HR 是监督训练的目标。
- LR 由对应 HR 图像生成。
- 训练和验证数据必须隔离。
- HR 与 LR 裁剪位置必须严格对应。
- 不允许将不同图片的 HR 和 LR 错误配对。
- 随机增强必须同步应用于 HR 和 LR。
- 固定随机种子并记录。
- 训练和验证退化流程必须明确记录。

## 6.2 LR 生成规范

训练数据退化方式采用 Bicubic 降采样。

2×：

\[
W_{LR}=W_{HR}/2,\quad H_{LR}=H_{HR}/2
\]

4×：

\[
W_{LR}=W_{HR}/4,\quad H_{LR}=H_{HR}/4
\]

必须在阶段 4 或阶段 5 详细设计中冻结具体实现：

- 使用的图像库和插值实现。
- 边界处理。
- 尺寸取整策略。
- RGB 数值范围。
- 是否使用抗锯齿。
- 验证集是否使用同一退化协议。

不能默认 PIL、OpenCV 和其他库的 Bicubic 实现完全相同。

正式实验一旦冻结退化配置，训练、验证和最终评价必须遵循对应协议。

## 6.3 Patch 训练

由于 RTX 4050 Laptop 只有 6GB 显存，采用 Patch-based 训练。

要求：

- 不将完整高分辨率图像直接全部送入模型训练。
- 使用固定或受控的 Patch 尺寸。
- HR 和 LR Patch 严格对应。
- 根据模型和显存情况调整 Batch Size。
- 记录显存峰值和每个 Epoch 的耗时。

具体 Patch 尺寸、Batch Size 在小批量测试后确定，不预先强制使用不适合显存的参数。

## 6.4 损失函数与优化器

首选：

- L1 Loss。
- Adam 优化器。
- 固定随机种子。
- GPU 训练。
- 验证集监控。
- 保存最佳验证权重。
- 支持断点续训。

具体学习率、Batch Size、Epoch 数和调度器必须通过小规模实验确定并记录。

# 第七部分：评价体系

## 7.1 评价目标

评价不同算法的图像重建质量和运行效率。

比较对象：

- 最近邻插值。
- 双线性插值。
- 双三次插值。
- SRCNN。
- ESPCN。

## 7.2 PSNR

峰值信噪比（Peak Signal-to-Noise Ratio）用于衡量重建图像与参考图像之间的像素误差。

\[
PSNR=10\log_{10}\left(\frac{MAX^2}{MSE}\right)
\]

数值通常越高，代表像素级重建误差越小。

## 7.3 SSIM

结构相似性（Structural Similarity Index）用于衡量图像在亮度、对比度和结构方面的相似程度。

数值越接近 1，通常代表结构相似程度越高。

## 7.4 评价协议

阶段 6 必须统一并记录：

- RGB 或 Y 通道评价口径。
- 图像边缘裁剪规则。
- 像素值范围。
- 数据类型。
- 图像尺寸匹配规则。
- SSIM 窗口和计算实现。
- 测试集退化方法。
- 模型推理计时范围。

不得混用不同评价协议下的指标。

建议保留 RGB 视觉展示，并根据课程实验方案确定统一的定量评价口径。

## 7.5 推理耗时

推理耗时需要明确：

- 是否包含模型加载。
- 是否包含图像预处理。
- 是否包含 GPU 数据传输。
- 是否包含 GPU 同步。
- 是否包含输出后处理。

模型推理计时应进行预热，并使用多次测量的统计值，而不是仅报告一次运行结果。

传统插值和深度学习模型的计时条件应分别说明。

## 7.6 评价结果

输出：

- PSNR 数据。
- SSIM 数据。
- 推理耗时。
- 不同算法的对比表。
- 不同算法的对比图。
- 不同测试集的结果。
- 典型图像局部细节对比图。

对于没有 HR Ground Truth 的用户上传图片，只能展示重建图像和处理耗时，不能计算 PSNR、SSIM。

# 第十一部分：多智能体协作与监督规范

## 11.1 总体原则

Gemini 4 Hydrogen 是主要实现 Agent。

其他智能体作为独立监督者，不是多个智能体共同随意修改代码。

项目负责人拥有最终决策权。

多智能体的职责：

- 实现 Agent：编写和修改代码。
- 架构审查 Agent：检查设计合理性和模块边界。
- 代码审查 Agent：检查具体实现和潜在缺陷。
- 测试审查 Agent：独立检查测试覆盖率和测试有效性。
- 实验审查 Agent：检查数据、指标、训练记录和结果真实性。

可以根据可用智能体数量合并角色，但不能让实现 Agent 同时充当唯一验收者。

**2026-11-13 补充（会话隔离硬性要求）：** 自阶段 5 起，**任务书作者、实现 Agent、审查 Agent 必须运行在相互独立的会话中**，三者之间只通过磁盘文件交接，不得通过对话上下文传递实现细节、判断结论或历史讨论。具体危害分析与交接启动包清单见 `docs/PHASE_05_TASK_SPEC.md` 第十一章。

简化的角色分工：

| 角色 | 写什么 | 不做什么 |
|---|---|---|
| 任务书作者 | 只写 `docs/` 下的任务书与规范 | 不写代码、不参与审查、不对验收投票 |
| 实现 Agent（独立会话） | `src/`、`scripts/`、`configs/`、阶段报告 | 不改任务书、不自我验收、不擅自进入下一阶段 |
| 审查 Agent（独立会话，只读） | 只写 `docs/PHASE_XX_REVIEW.md` | 不改任何实现文件、不采信"已修复"陈述 |

## 11.2 实现 Agent 工作规范

实现 Agent 必须：

1. 先读取项目文档。
2. 检查当前项目实际代码。
3. 明确当前阶段。

5. 修改前检查现有文件。
6. 不覆盖无关内容。
7. 不改变冻结需求。
8. 不擅自升级依赖。
9. 不伪造测试结果。
10. 不进入未经批准的下一阶段。

每次交付必须说明：

- 修改了什么。
- 为什么修改。
- 修改了哪些文件。
- 执行了什么命令。
- 实际测试结果。
- 尚存问题。
- 是否影响其他模块。

审查重点：

- 模块职责是否清晰。
- 输入输出是否统一。

## 11.5 测试审查 Agent

重点检查：

- 测试是否真正执行。
- 测试是否覆盖关键边界。
- 测试是否只验证表面结果。
- 是否存在测试代码和实际实现使用同一错误假设的问题。
- 是否有独立构造的测试输入。
- 是否能复现测试结果。
- 是否检查了异常路径。

不得接受只提供“测试通过”文字而没有命令和实际输出的报告。

## 11.6 实验审查 Agent

重点检查：

- 数据集是否正确。
- 训练集与验证集是否隔离。
- LR 和 HR 是否正确对应。
- 是否存在数据泄漏。
- 是否真正从随机初始化开始训练。
- 训练日志是否连续可信。
- 最佳权重是否与日志对应。
- 指标计算协议是否一致。
- 是否存在不合理的实验结论。

不同审查 Agent 不应直接修改同一工作区。
